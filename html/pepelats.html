Features

  • Compatible Raspberry Pi: 3A+, 3B+, Zero-2W, 4, 5

  • Multiple song parts (intro/verse/chorus/...).

  • Any number of parallel loops in a part.

  • Quantization, loop's length, start and stop time are adjusted.

  • Full history of undo/redo for each song part.

  • Parts and loops are deleted on the run, loops are silenced, re-arranged.

  • Songs saved, loaded along with drums and settings.

  • Installation with single command.

  • MIDI controller or computer keyboard as MIDI controller.

  • Three drum machine types with volume control, random variations and breaks.

Installation

  • Read this document to understand specific configurations.

  • Install latest Raspberry Pi OS Lite 64 bit. I recommend rpi imager that allows to configure WiFi (network ID and password). Assign host name (example: loop).

  • Connect keyboard and HDMI display or, better, connect via SSH from another computer and run this command to install looper.

wget -qO- https://github.com/slmnv5/pepelats/raw/refs/heads/main/install.sh | bash

  • Connect MIDI controller and make sure it's name (or part of name) is listed in user.ini file.

  • Also check that MIDI controller notes for you specific controller are listed in user.ini

  • If your MIDI controller use Bluetooth you need to run few commands on Raspberry Pi to pair / connect it.

  • You may skip the 3 steps above if you use computer keyboard instead of MIDI controller as described below. I highly recommend doing this.

  • Finally you need to check log file for any errors related to MIDI connection or audio device connection. All these steps you may do on the application main page that has links to configuration and log files.

Important files you may view / edit from main web page

  • log.txt – log file for current session

  • old.txt – log that keeps about 1000 lines from past sessions

  • main.ini – default configuration, serves as an example

  • user.ini – user specific configuration, overrides defaults

  • license.ini – user's email and license number


Important directories

  • ~/save_song – directory where song files are saved

  • ./config – directory where configurations for drums and menus are stored



Configuration details

All configurations are in two files:

  • [user.ini] - user configuration, edit this file if you need changes

  • [main.ini] - contains all default configurations and comments explaining each option

If file user.ini does not have specific configuration it is taken from file main.ini. You may edit file user.ini on the main web page: [looper].

Configurations for audio

  • audio_names – list of names (or part of names) of audio devices, case-sensitive. First found device in the list will be used. If nothing is found looper will start with “Fake Audio” and you may check the log to see connected Audio devices and errors.

Configurations for MIDI controller

  • midi_in_names – list of names (or part of names) for MIDI input controls, case-sensitive. First found device in the list will be used. If nothing is found looper will try to use computer keyboard. If later is not found looper will start with “Fake MIDI” and you may check the log to see connected MIDI devices and errors.

  • midi_values – MIDI notes (or CC) numbers that MIDI device sends. This is list of integer values from 0 to 127.

  • keyboard_keys – computer keyboard keys to use for MIDI messages. Defaults are: 1, 2, 3, 4, q, w

Checking errors and correcting configurations

If MIDI input and / or audio device not found the looper starts anyway and saves errors in the log. There are 3 ways to run it and fix any issues

  • No physical screen connected and no SSH connected – looper uses Web page and you can check log for errors, edit configurations and restart.

  • Physical screen connected to Raspberry Pi – loper uses this screen. You need computer computer keyboard to check logs and edit configurations.

  • Looper started via SSH connection – looper uses SSH terminal. You can see logs, edit configurations and start it again in this SSH connection.

MIDI commands

Multi-tapping

There are only few buttons on foot controllers and number of looper commands is much bigger. To deal with it multi-tapping is used. If delay between taps is less than 0.5 seconds they belong to one series and produce MIDI note as explained below.

Assume button A sends note ON for note 60 with velocity 100. Multiple tapping will send one additional note ON for note 60 with changed velocity.
One additional note ON message will have velocity = number of taps + 5 if there is a hold in the end. For this example:

  • one tap sends note 60 velocity = 100 + note 60 velocity = 1

  • double tap sends note 60 velocity = 100 + note 60 velocity = 2

  • triple tap sends note 60 velocity = 100 + note 60 velocity = 3

  • one tap and hold sends note 60 velocity = 100 + note 60 velocity = 1 + 5 = 6

  • double tap and hold sends note 60 velocity = 100 + note 60 velocity = 2 + 5 = 7

Using multi-taps one button sends different MIDI messages with velocities 1,2,3... Multiple taps use 0.5 seconds delay to see if there is next tap. Because of this it should not be used for time critical commands – like play start or stop. Use it for other commands like changing volume, scrolling song list, etc.

Menu files – link buttons, MIDI messages and actions

In menu files we use button label A and number of taps to assign actions:

  • A: play

  • A1: overdub

  • A2: stop: stop drum

Here A – is original note sent instantly without any delay (note 60 with original velocity). A1, A2 – are counted notes delayed by 0.5 seconds + time it takes to tap 1 or 2 or times (note 60, velocity 1 and 2 respectively).

Control change MIDI messages

If foot controller sends control change (CC) messages from expression pedal the looper can convert them into notes. As example CC 12 will be converted to note 12 ON/OFF.

If a MIDI controller has expression pedal input we may plug ON/OFF button and use it with the looper. This is how 2 more buttons were added to iRig BlueBoard MIDI controller.

Menu

As explained above menu configurations are INI files that link together button labels, MIDI messages and looper commands. Additionally menu files have two options:

  • description – text appearing on top of screen when menu is loaded, just below the loop progress bar.

  • show – a command to display looper information on screen

There are only 3 menu configurations files.

  • [play.ini] -- play / record / clear song parts and switching between them. Show loops for song part. Silence, delete, re-arrange loops.

  • [song.ini] - delete, save, load, initialize song. Select drum configuration.

  • [serv.ini] - Restart looper, show hardware ID and license. Select drum type, adjust drum volume, parameter.

Each menu INI file has two sections with different but related commands. As an example play menu has section to work with song parts and section to work with loops inside one part. Also note that there may be multiple commands separated by colon (:) assigned to one button.

Menu view on screen

When switching menu file or menu section the look of the screen changes. However there is common information shown for each menu. Namely the top row always shows progress bar. It includes position of the loop, current song name, drum configuration and beats per minute.



Song

Song is collection of recorded song parts along with specific drum type and drum configuration. Songs are saved in user's home directory ~/save_song.

Song names are 'random words' and look like "bib-duhi.Disco.k48", "le-ebaka.Blues.k44". Names include Drum style (Disco, Blues, ...) and sampling frequency (.k48 – 48 kHz, .k44 – 44.1 KHz). The later prevents loading song recorded on a devices with different sampling frequency.

Screen

Looper outputs its state on:

  • text screen – attached screen via SPI or HDMI connection

  • web page – HTTP://loop.local:8000 Here 'loop' is host name of raspberry pi and HTTP port is always 8000

If screen is attached – it is used, otherwise web page is used to output looper state.

  • Web page pros: It allows you to to see log files, edit configuration files, restart looper.

  • Web page cons: You need to carry a device with web browser (phone, tablet) that is connected to the same WiFi as the looper.

  • LCD screen pros: If we use special 3.5 inch LCD for Raspberry Pi it will make a simple compact looper that does not need WiFi connection.

  • LCD screen cons: Hard to change configuration or check logs for errors. Best way is connect Raspberry Pi to WiFi and use another computer over SSH connection.

Drums in general

Looper has embedded drum machine that may use different drums:

  • Style drum – using text patterns – with drum names, steps and accents

  • MIDI drum – using configurations to send MID commands (stop, set BPM, start of loop, etc.)

  • Loop drum – the first recorded song part becomes a drum track.

Drum breaks

There are two modes for drums – normal beat and break. Different types of drums implement breaks as described here.

  • Style drum patterns are split into 2 groups based on the name – if pattern name contains string "brk" it is used for breaks otherwise it is used for beats.

  • Loop drum mutes some loops to play breaks. How loops are selected for a break is described below.

  • MIDI drum break may be configured in INI file by sending specific MIDI command. This command may be program change or other command specific for connected drum machine.

Drum randomness

Every drum has randomness parameter that can be adjusted and saved with the song. If this parameter = 0.5 then there is 50% chance that drum pattern will be randomized at start of bar. For new song this parameter = 0.1



MIDI drum

MIDI drum sends MIDI messages to external drum machine to synchronize it with the looper, change drum volume, program number, etc. Processing of MIDI messages is done by external hardware drum machine or by another application.

Set of MIDI messages along with the MIDI OUT port name are saved in configuration file. There are three predefined configurations that may serve as examples.

  • [ValGP-100.ini] - Valeton GP100 guitar pedal with drums.

  • [MidiFire.ini] – MidiFire IOS application that sets dynamic MIDI clock and can control other IOS drum applications.

  • [FunkBox.ini] – Funk Box IOS drum application.

MIDI messages used in configuration

There are six messages to control MIDI device, each may contain variables:

  • bpm_msg – sent only once when the BPM is defined (when loading song or recording the 1st loop)

  • bar_msg – sent at start of each bar. Note, there is no start message, instead this message is used

  • stop_msg – stops drum.

  • volume_msg – changes volume (ex: CC #7 from 0 to 127)

  • prog_msg – selects drum program / pattern, used for drum breaks and randomizing drums.

MIDI variables used in configuration

Six variables may be used in messages (all upper case names):

  • BPM – beats per minute, ex. 123.89

  • BPM_LIST - [0, 1, 2, 3, 8, 9] - is byte list of BPM = 0123.89

  • PROG – program number, from 0 to 127

  • VOLUME – volume from 0.0 to 1.0

  • COUNT – count of bars since the latest re-start

MIDI out port for MIDI drum

Each drum configuration INI file has option "midi_out_name". This is MIDI port name (or part of the name) used to send MIDI drum messages. If port is not available (device is not connected) the drum still be loaded but messages not sent. Drum configuration view will show port drum name as "None". After MIDI drum is connected you need to re-load song or set drum configuration file so that looper will connect to the port.

Style drum

Style drum is using text patterns specific for musical style and sample WAV files to produce drum accompaniment. Each style pattern sits inside one section of INI file. Number of steps is equal to the longest drum length. Two examples of styles are below.

[Metronome] – patterns for metronome

[Blues] – patterns for blues

Drum names

Drum names used in pattern INI file and WAV file names are the same (ex. sd.wav, bd.wav): 

bd: Bass drum 
sd: Snare drum 
lt: Low tom 
mt: Medium tom 
ht: High tom 
ch: Closed hi-hat 
oh: Open hi-hat 
cy: Cymbal 
rs: Rim shot 
cp: Clap 
cb: Cowbell

Loop drum

Loop drum is recorded song part that plays along with other parts. As a song part Loop drum may have several parallel loops and it is randomized by muting some of the loops.

It has INI configuration with options that define how drum is randomized and how breaks are played. Example: [Loop drum configuration]

Troubleshooting errors

Sometimes your audio device may have issues with audio capture or playback volume. To fix you need install a package:

sudo apt install alsa-utils

This will give you nice text user interface (TUI) command so that you can set playback and recording volumes:

alsamixer

I recommend setting all levels for playback and recording around 90%. If your direct sound (before recording) sounds much louder you may decrease capture level.

Advanced audio devices as a rule have all these levels regulated in hardware. Only basic USB devices that do not have any knobs need adjusting levels by software settings.

To save the setting that you made run this:

sudo alsactl store

Setting are saved for each device separately. You may switch USB audio devices and after reboot proper setting will be loaded.

Troubleshooting errors

If you have errors you need to connect to Raspberry pi box using SSH and run this commands:

cd ~/pepe; 
./loop.sh --debug; 
cat log.txt

The logging levels: --warn, --info and especially –-debug will provide more details in the log file.

Finally, if you connect via SSH and want to run looper and work with logs and configuration using web browser run this:

cd ~/pepe
./loop.sh --debug –web
